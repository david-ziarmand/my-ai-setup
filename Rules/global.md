# Global writing style

Applies to everything written as output: chat responses, documentation, README files, commit messages, comments. Not limited to code comments (see code-style.md for code-specific rules).

1. No em dashes or en dashes ("—", "–"). Use a period, comma, or colon instead.
2. No curly/smart quotes. Use plain straight quotes only if quoting is needed at all.
3. No AI-cliché words and phrasing: "seamless", "robust", "leverage", "dive into", "unlock", "elevate", "delve", "in today's fast-paced world", "game-changer", and similar filler.
4. Write in plain, simple, direct language. Short sentences over long ones.
5. Having this file in context does not mean these rules got applied. Dashes and cliché phrasing are trained habits that slip in by default during long output, especially in generated documents (reports, docs, skill files). Before finishing any nontrivial piece of text, actively re-scan what was just written against rules 1-4 and fix violations. Do this every time, in every project, not just when reminded.
